# ADR：个人 AI 连接器采用“宿主生成、主人确认、平台最小接收”

- 状态：Accepted
- 日期：2026-09-17
- 适用范围：Handshake V1 的 ChatGPT、Kimi、豆包接入

## 问题

Handshake 希望让 A 的常用 AI 和 B 的常用 AI 帮主人完成搭档初筛。难点在于：ChatGPT、Kimi、豆包的个人 Memory 属于各自账号和客户端的内部能力，第三方平台不能把一个普通模型 API Key 当成读取消费端账号 Memory 的钥匙；不同客户端对 MCP、插件和后台回调的支持也不一致。

如果平台假装已经“接入个人 Memory”，会产生两个问题：产品承诺不真实，而且会诱导用户交出 Cookie、完整聊天或过量个人数据。

## 决策

V1 不读取供应商账号 Memory，而是提供两条等价的最小披露路径：

1. **交互式 MCP/插件路径**：当用户当前使用的 AI 客户端确实支持兼容工具时，宿主 AI 使用它在当前会话中本来就有权使用的上下文，生成结构化工具参数。Handshake MCP Adapter 只转发这些参数，不能反向查询宿主 Memory。
2. **Capsule 导入路径**：用户要求任意 AI 按公开 Schema 生成任务专用 JSON，在成员页面粘贴后逐字段批准。该路径不要求供应商提供 MCP，也是 V1 的通用兜底。

两条路径最终都生成同一种 `MemoryCapsule`。Capsule 只服务 `seven_day_portfolio_teamup`，只包含目标、可提供/需要的能力、时间、协作方式、兴趣、地点模式和语言；原始聊天、完整 Memory、凭据和联系方式不属于 Capsule。

## 供应商策略

| 宿主 | V1 首选路径 | V1 兜底 | 明确不承诺 |
| --- | --- | --- | --- |
| ChatGPT | 仅在具体客户端/工作区提供兼容 MCP 或插件入口时使用交互式工具 | Capsule 导入 | OpenAI API 自动继承 ChatGPT 账号 Memory |
| Kimi | 仅在当前客户端提供兼容 MCP/插件入口时使用交互式工具 | Capsule 导入 | Handshake 可直接读取 Kimi 全局记忆 |
| 豆包 | Capsule 导入 | Capsule 导入 | 未经验证的 Memory 读取、Cookie 抓取或后台自动唤醒 |

能力按连接实例声明，而不是按品牌硬编码。当前类型区分：

- `capsule_import`：能生成并导入 Capsule；
- `interactive_tool`：能在用户当前会话中调用 Handshake 工具；
- `background_callback`：能在用户离线时被平台唤醒。V1 只保留能力概念，不假设任一供应商支持。

## 授权流程

```text
原 AI 当前可用的上下文
        │ 生成 Capsule 草稿
        ▼
用户逐字段批准 ── 发布 ──> 发现与可解释匹配
                               │
                         有限结构化问题
                               │
                     用户确认最小 Claim
                               ▼
                      双方 AI 分别建议
                               │
                   两位主人同意同一版本
                               ▼
                         揭示联系方式
```

- 未传 `approvedFields` 等同于没有批准任何字段。
- 发布、发送 Claim 和主人决定都是显式确认动作；AI 建议不等于主人同意。
- 每个 Claim 绑定目的、接收方、来源、置信度、到期时间和 `ownerConfirmed`。
- 联系方式由 Platform API 执行双重同意规则，MCP Adapter 和前端都不能提前获得。

## 被拒绝的方案

- **让用户填写模型 API Key**：API Key 调用模型服务，但不会自动获得消费端账号的个人 Memory；还扩大了密钥风险。
- **上传完整聊天/导出文件到 Handshake**：能增加上下文，但违反最小披露原则，也让平台承担不必要的敏感数据责任。
- **浏览器自动化、Cookie 或页面抓取**：脆弱、不可审计，并可能绕过供应商和用户授权。
- **把公开资料卡当作全部事实**：资料卡适合检索，但无法确认某次合作的临时硬条件；V1 保留最多 3 轮的目的限定问答。
- **默认后台 AI 对 AI 自动聊天**：MCP 通常是用户会话内的工具调用，不能据此推断宿主支持离线唤醒。V1 由人触发并随时可见。

## 结果

这项决定降低了“全自动代理社交”的表面自动化程度，但获得了可实现、可解释且可演示的产品边界。新增供应商时，只能通过相同 Capsule/Claim 契约接入；任何读取账号级 Memory 或后台回调能力，都必须先用供应商正式能力验证并另立 ADR，不能作为品牌名称的默认能力。
