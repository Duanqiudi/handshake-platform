# ADR-0001：平台后端先采用模块化单体

- 状态：Accepted
- 日期：2026-09-14

## 背景

首版需要同时验证协议、信任边界和用户闭环，团队与十二周试点周期不足以合理承担服务发现、跨服务事务、分布式调试和多套值班体系。与此同时，身份、发现、会话、授权和安全必须有清楚的所有权，避免成为无边界单体。

## 决策

- 平台业务能力先在一个版本化仓库中按模块组织。
- `gateway-api` 和 `gateway-worker` 是两个部署进程，共用领域与 Adapter 包；Web 和本地 Reference Agent 独立部署。
- PostgreSQL 是持久事实来源；Redis 只承担可丢失的在线状态、限流、短锁和缓存。
- 跨异步边界使用 Transactional Outbox 和幂等 Consumer，不在请求事务中依赖消息投递成功。
- 每个业务模块拥有自己的表和 Repository；跨模块使用公开用例/查询接口或领域事件。
- 拆分服务必须新建 ADR，并满足 `delivery-phases.md` 的硬触发条件和准备项。

## 结果

好处：本地开发、测试、部署和事务一致性简单；领域边界仍可独立演进并为未来拆分保留接缝。

代价：进程级故障和扩缩容暂时共享；必须持续执行依赖规则，否则会退化为大泥球。

## 审查信号

每季度或出现持续 SLO 违约时审查本决策。审查材料必须包含 Trace/容量数据、故障记录、团队责任人、预计迁移成本和回滚方案，不能仅凭代码量决定拆分。
