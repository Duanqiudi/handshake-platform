# Handshake V1 产品范围

状态：实现基线  
最后更新：2026-09-17

## 一句话定义

Handshake 让正在求职、转行或学习 AI / 产品 / 开发的人，带着自己常用的 AI，在 7 天内找到互补搭档并完成一个作品集项目。

## V1 的完整闭环

1. 用户创建本地邀请制账号并登记联系方式；联系方式默认私密。
2. 用户通过 MCP、AI 生成内容导入或合成演示连接自己的常用 AI。
3. 原 AI 根据它当前可用的上下文生成任务专用 Memory Capsule 草稿。
4. 用户逐字段检查、批准并发布 Capsule；Handshake 不接收原始聊天或完整 Memory。
5. 用户发布一个 7 天项目意图，平台进行硬条件过滤和可解释的互补匹配。
6. 候选双方建立 Handshake，AI 可提出有限轮次的结构化问题。
7. 回答仅以经主人确认的最小 Claim 发送，并记录用途、接收方和到期时间。
8. 双方 AI 分别给出继续、人工复核或拒绝建议。
9. 两位主人基于同一版本的披露摘要分别同意；第二次同意前 API 不返回联系方式。
10. 双方同意后建立 7 天项目空间，记录计划、每日进展、作品和合作反馈。

## 三种 AI 接入能力

| 能力级别 | 含义 | V1 支持 |
| --- | --- | --- |
| `capsule_import` | 用户让原 AI 生成标准 Capsule，再导入 Handshake | 是 |
| `interactive_tool` | 原 AI 在当前会话中通过 MCP 调用 Handshake 工具 | 是 |
| `background_callback` | 用户离线时，原 AI 可被外部事件唤醒并自动回答 | 仅声明能力，不假设供应商支持 |

MCP Server 不读取宿主 AI 的 Memory。宿主 AI 自己使用当前可用的 Memory/上下文生成工具参数，Handshake 只收到用户允许发布的字段。

## V1 唯一业务场景

- 人群：正在求职、转行或学习 AI / 产品 / 开发的人。
- 目标：7 天组队完成一个可以放进作品集的项目。
- 匹配依据：互补技能、共同项目方向、投入时间、协作方式和硬性限制。
- 交流预算：最多 3 轮，每轮最多 3 个问题。
- 成功事件：双方同意联系、创建项目、提交作品、完成双方反馈。

## 不冒充已完成的能力

- 不宣称 Handshake 能直接读取 ChatGPT、Kimi 或豆包账号 Memory。
- 不把 API Key 描述成消费端账号 Memory 的钥匙。
- 不使用浏览器 Cookie、会话劫持或页面抓取读取个人 AI 数据。
- 不宣称所有 AI 都支持离线后台唤醒。
- 合成演示连接必须在界面中明确标为演示数据。

## 产品安全不变量

- 原始聊天、完整 Memory、私钥和供应商 API Key 不进入中心数据库。
- Capsule 撤销后立即退出发现结果。
- 联系方式在双方同意前不进入 API 响应和页面 DOM。
- 每个 Claim 绑定用途、接收方、来源、过期时间和主人确认状态。
- 用户拒绝或撤销后，平台不能继续扩大披露。
- 演示数据只能使用合成身份和 `.example.test` 联系方式。

## 本地 V1 与生产版的边界

本地 V1 提供真实业务闭环、SQLite 持久化、Bearer 邀请令牌、通用 MCP、成员 Web 和自动化测试。生产上线前仍需替换/补齐：正式 OAuth/身份验证、Endpoint 密钥签名、托管 PostgreSQL、可靠通知与 Outbox、云端密钥管理、供应商实机认证、法律与隐私评审。
