# 运行手册索引与编写标准

Runbook 的目标是让当班人员在不了解实现细节时也能安全止损、验证恢复并留下证据。任何会触发生产告警的能力，在进入试点前必须有对应 Runbook 和演练记录。

本地产品展示使用独立的 [`interview-demo.md`](./interview-demo.md)。它是演示前检查和故障备用路径，不等同于生产事件响应 Runbook。

## 必备清单

| Runbook | 建议触发信号 | 试点前要求 |
| --- | --- | --- |
| `hsp-signature-or-replay.md` | 签名失败或 nonce 重放率突增 | 必须完成 |
| `queue-backlog.md` | Outbox 最老未投递年龄超过 SLO | 必须完成 |
| `expired-data-deletion.md` | C3 最老过期记录大于 24 小时 | 必须完成 |
| `cross-tenant-or-data-exposure.md` | 疑似跨 Community 访问或敏感数据外泄 | 必须完成并演练 |
| `model-provider-outage.md` | 供应商错误率/限流持续超阈值 | 必须完成 |
| `database-restore.md` | 主库不可恢复或误删 | 必须完成恢复及删除墓碑重放演练 |
| `key-rotation.md` | 例行轮换或疑似密钥泄露 | 必须完成 |
| `rollback-release.md` | 灰度关键指标超过停止线 | 必须完成 |

阶段 1 只建立本索引和模板；阶段 2 随实际基础设施补充可复制命令；阶段 4 前必须逐项由非作者演练。命令、Dashboard 和负责人尚未存在时必须标为 `TBD（阻止试点）`，不得编造。

## 每份 Runbook 模板

```markdown
# <事件名称>

- Owner / Backup：
- 影响的 SLO 与数据级别：
- Dashboard / Alert：
- 最近验证日期：

## 进入条件
明确告警阈值、用户症状和不适用情况。

## 0–15 分钟：止损
1. 宣布事件等级并建立事件记录。
2. 保存 Trace ID、版本、时间窗等最小证据；不要复制正文或密钥。
3. 执行可逆的限流、熔断、暂停写入或回滚。
4. 指定事件负责人、沟通负责人和记录人。

## 诊断
按低风险到高风险列出只读检查、预期结果和分支判断。

## 缓解与恢复
列出精确命令、权限、影响范围、回滚步骤；破坏性操作需要双人复核。

## 验证
验证积压归零、端到端探针、数据边界、SLO 和用户影响，而不只是进程存活。

## 沟通
内部更新频率、用户/监管通知的决策人及模板链接。

## 事后
时间线、根因、影响面、数据删除/恢复核对、行动项 Owner 和截止日期。
```

## 通用处置规则

- 优先采取可逆、最小范围措施；禁止为排障关闭租户校验、签名校验、审计或数据删除。
- 生产查询默认只读且不得输出 C3/C4。确需受限正文时，使用临时授权、工单原因和全量访问审计。
- 删除、密钥吊销、跨租户或疑似泄露事件必须由两人复核；一个人执行，另一个人确认目标与结果。
- 所有命令先写明目标环境和租户；不得使用无范围的通配符删除或更新。
- 恢复成功以业务探针、积压、错误率、数据一致性和安全控制同时正常为准。
- 每次重大事件和每季度至少复核相关 Runbook；命令或架构变化的 PR 必须同步更新。

数据事件的分级、披露与法务时限由正式 Incident Response Policy 决定。在该政策批准前，疑似跨租户访问、C4 进入中心端、私钥泄露或无法停止的数据外传均按最高内部优先级升级，不等待确认影响人数。
